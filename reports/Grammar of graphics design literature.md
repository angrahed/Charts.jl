# Design the grammar once, render it twice

The research literature and current practice point to one architecture for a new Julia charting language. Keep ggplot2's layered grammar and, above all, its hierarchy of defaults. From the first release, also build in the five things ggplot2 had to retrofit or leave to extensions: annotations with data targets, interaction semantics expressed as data-space selections, mixed-unit positioning with invertible scales, a public renderer-neutral scene, and a single semantic theme tree. Every chart should compile in Julia to a fully resolved scene, with text measured from real font files. That scene is then emitted twice: to vector print output, and to a self-contained HTML/JavaScript runtime that provides Highcharts-style behaviour (tooltips, hover dimming, legend toggling, zoom, drilldown) without a Julia process. Defaults should encode the consistent consensus of newsroom and government house styles, plus the perceptual evidence, as a revisable rule table rather than constants, because channel-effectiveness rankings now look task-, data- and person-dependent ([Kim & Heer 2018](https://idl.cs.washington.edu/files/2018-TaskDataEffectiveness-EuroVis.pdf); [Zeng & Battle 2023](https://arxiv.org/abs/2109.01271)). Highcharts itself cannot be the bundled backend. Its January 2026 EULA limits free use to personal and accredited-education settings and forbids redistributing the JavaScript ([Highcharts EULA 1.0](https://shop.highcharts.com/license-eula-1.0.pdf)), so "Highcharts-style" has to mean reimplemented behaviour; Apache-2.0 ECharts and BSD-licensed Vega-Lite are the permissive emitter targets. The Julia gap is specific and well documented. Makie and AlgebraOfGraphics already produce strong static figures, but no Julia-native grammar exports shareable interactive 2-D HTML, and Makie's lead developer said in February 2026 that "nothing much has changed yet for 2D plots" ([Julia Discourse](https://discourse.julialang.org/t/interactive-line-plots-in-documentation/135537)). Three things are still unknown. No user study has validated this combination of features. Vendor guidance, not peer-reviewed benchmarks, sets the SVG/Canvas/WebGL thresholds. And owning a JavaScript runtime is the project's largest maintenance risk.

## ggplot2's decade of retrofits shows which decisions cannot wait

ggplot2's history is the best evidence of which design choices are expensive to change later. A ggplot is a lazy, immutable specification that becomes a picture in two stages. `ggplot_build()` computes statistics, positions and trained scales, then `ggplot_gtable()` lays out grid objects; ggplot2 itself draws nothing ([ggplot2 book, Internals](https://ggplot2-book.org/internals.html)). The split has paid off. plotly's converter, ggiraph and a 2026 Rust re-implementation all consume the build output, and ggplot-rs validates its statistics against ggplot2 4.0.3, the current release ([ggplot-rs](https://github.com/sipemu/ggplot-rs)). Much of the rest arrived late. Guides were "the only major system in ggplot2 still clinging to the S3 system" until **3.5.0 in February 2024** ([ggplot2 3.5.0](https://www.tidyverse.org/blog/2024/02/ggplot2-3-5-0/)). Layer defaults moved into the theme only in **4.0.0 in September 2025**, answering a request opened in August 2017 ([#2239](https://github.com/tidyverse/ggplot2/issues/2239); [ggplot2 4.0.0](https://tidyverse.org/blog/2025/09/ggplot2-4-0-0/)). The same release moved user-facing classes to S7 and broke **about 64 reverse dependencies** on label handling, plus about 8 more on stricter property types ([#6505](https://github.com/tidyverse/ggplot2/issues/6505)). Writing extensions still requires knowing the internals, which is "typically beyond that of most users" ([Tanaka 2025](https://arxiv.org/abs/2510.10382)).

Users mostly struggle with presentation, not the grammar. The ggplot2 tag holds 57,661 Stack Overflow questions. The top-voted ones ask how to rotate axis labels (**929 votes, 1.78 million views**), put two graphs in one plot, change a legend title, place plots side by side, set axis limits, centre a title and draw two y axes. The title question was asked in November 2016, right after titles became left-aligned by default ([Stack Exchange API, Oct 2026](https://api.stackexchange.com/2.3/questions?order=desc&sort=votes&tagged=ggplot2&site=stackoverflow)). An observational study of analysts found the friction sits between data space and aesthetic space. Participants hard-coded data values to place annotations because "there are no inverse scale functions to map aesthetic space values back to the data space". One passed a hex colour that was treated as a data value. Several produced plausible but wrong plots without any error ([Pu & Kay 2023](https://xiaoyingpu.github.io/files/pu2023how.pdf)). Units are a long-standing mess: line width is "roughly 0.75 mm" because of "a historical error", text is sized in millimetres, and output in inches ([ggplot2 specs vignette](https://ggplot2.tidyverse.org/articles/ggplot2-specs.html)). Interactivity was never designed in. "ggplot2 doesn't provide an API for interactive features", so `ggplotly()` has to guess trace attributes after the fact ([Sievert, plotly-r.com](https://plotly-r.com/improving-ggplotly.html)). The 167 registered extensions ([ggplot2 extensions gallery](https://exts.ggplot2.tidyverse.org/gallery/)) keep filling the same gaps:

Read against this evidence, "more customizable than ggplot2" means removing cliffs, not adding knobs. Heer and Bostock frame the trade-off as expressiveness, efficiency and accessibility. They place GoG-level systems at an abstraction that does "not provide fine-grained control over graphics and interaction" ([Heer & Bostock 2010](https://idl.cs.washington.edu/files/2010-Protovis-InfoVis.pdf)). Satyanarayan and colleagues restate it as a threshold for learning and a ceiling for expressivity ([Satyanarayan et al. 2019](https://idl.cs.washington.edu/files/2019-ReflectionsVisAuthoring-InfoVis.pdf)). Wongsuphasawat places grammars one level below Highcharts-style building blocks, noting that "higher-level libraries usually require fewer lines of code… but then there are fewer things you can customize" ([Nightingale 2020](https://nightingaledvs.com/navigating-the-wide-world-of-data-visualization-libraries/)). A metrics study of nine notations found that ggplot2, Vega-Lite and Altair cluster together, with no "fundamental difference between DSL-based notations… and those based in general-purpose languages" ([Kruchten et al. 2023](https://arxiv.org/abs/2308.16353)). So the language should offer layered access within one system. High-level chart functions should return editable grammar objects, and grammar objects should lower to an inspectable mark-level scene with Protovis-style property inheritance. Every position should accept mixed units, every scale should be invertible, and the extension points should be Julia abstract types with documented method contracts rather than retrofitted class systems.

Some items can be added later and some cannot. The intermediate representation, the interaction semantics, annotation targets, the unit system and large-data statistics cannot be retrofitted without breaking changes. Composition, rich text, label repulsion and nested facets are API surface, but they dominate real questions and belong on the first-release list.

## The core needs two algebras, explicit layout operators and statistics with declared laws

Wilkinson's grammar is a closed system of DATA, TRANS, SCALE, COORD, ELEMENT and GUIDE statements. It has an algebra over variable sets: cross (`*`), nest (`/`) and blend (`+`), where "only blend is commutative" ([Wilkinson patent US7176924B2](https://patents.google.com/patent/US7176924B2/en)). Wickham's 2010 layered grammar re-parameterised this into independent layers (data and mapping, stat, geom, position), one scale per aesthetic, a coordinate system and a facet specification. It dropped DATA, TRANS and the algebra in favour of R's reshaping tools. Its decisive addition was an explicit **hierarchy of defaults**: geom↔stat pairs, scales chosen by aesthetic and variable type, and Cartesian coordinates. Wickham notes that GPL had defaults "but they are not described in the Grammar of Graphics" ([Wickham 2010](https://vita.had.co.nz/papers/layered-grammar.pdf)). That hierarchy, not the grammar, is what makes ggplot2 concise. A new language should therefore specify its defaults as part of the language semantics. It should also keep two load-bearing details from the 2010 paper. A scale is "a function, and its inverse", which is exactly what tooltips, crosshairs, brushing and zoom need. And the processing order is fixed (transform, then stat, then train, then map, then coordinate transform), because a log scale and a log coordinate system produce different smoothers.

The algebra question has three precedents that disagree. Polaris turned Wilkinson's algebra into a relational table algebra (concatenate, cross, nest) in which nest "only creates set entries for which there exist records", and every view compiles to SQL ([Stolte et al. 2002](https://graphics.stanford.edu/papers/polaris_extended/polaris.pdf)). Polaris also gives operator precedence as cross > nest > concatenation, while Wilkinson evaluates nest first. AlgebraOfGraphics reintroduced an algebra of a different kind, over specification fragments: `*` merges data, mapping and visual into a layer, `+` stacks layers, and distributivity factors out what layers share ([AoG tutorial](https://aog.makie.org/dev/tutorials/intro-i)). These are different objects, and the evidence supports having both. A spec-composition algebra in the AoG style gives reuse and partial templates, which addresses the informal "plot templates" analysts build by copy-paste ([Pu & Kay 2023](https://xiaoyingpu.github.io/files/pu2023how.pdf)). A small frame and facet algebra with Polaris-style nest and Wilkinson-style blend would let `y = [:sales, :profit]` place several columns on one axis, melted internally with a generated series key. Wide data is the most-cited friction in Julia's existing grammar. AoG's maintainer told a struggling user that a wide data frame "is not the most convenient format for AlgebraOfGraphics" ([Julia Discourse, Nov 2025](https://discourse.julialang.org/t/algebraofgraphics-documentation-frustrations/133903)). Whichever precedence is chosen should be documented explicitly.

Layout is where the grammar of graphics is weakest. Its descendants cannot agree on what stacking is. "In the original GoG, stacking occurs through a collision modifier, yet ggplot2 accomplishes it via position adjustments, Vega-Lite with an encoding channel, and Observable Plot through a data transform." Mosaics, waffles and ribbons "fall out of scope of most GoG implementations" ([Pollock & Satyanarayan 2025, GoFish](https://vis.mit.edu/pubs/gofish.pdf)). GoFish's answer formalises Gestalt principles as nestable operators: `Stack`, `Connect`, `Enclose` and `Frame`. Atom earlier showed that unit visualizations emerge from recursive layout operations rather than mark choice ([Park et al. 2018](https://pmc.ncbi.nlm.nih.gov/articles/PMC6995670/)). The practical design separates "what a mark looks like" from "where it is arranged". Stacking, dodging, waffling, packing and connecting should be composable layout operators over groups. A ggplot-like `position = stack()` remains the common-case surface, so these operators do not multiply into a zoo of special geoms. The data model needs the same honesty. The grammar of graphics assumes one tidy table ([Wickham 2014](https://www.jstatsoft.org/article/view/v059i10)). Wu et al. show that joining edges to nodes and then jittering or force-laying out the points breaks "referential integrity", so single-table grammars cannot faithfully express node-link diagrams, trees or treemaps ([Wu et al. 2025](https://arxiv.org/abs/2504.08979)). Allowing several named datasets per chart, with layers that reference each other by key, solves this. It also gives drilldown a clean parent-to-child link.

Statistics should declare algebraic properties, because interaction depends on them. Wickham required stats to be location-scale invariant. Bartonicek, Urbanek and Murrell show that linked selection and similar split-and-recombine interactions require group or monoid structure in the underlying statistics ([JCGS 2025](https://doi.org/10.1080/10618600.2024.2429708)). This applies directly to Highcharts-style legend toggling on a stacked chart. Sums and counts can be updated incrementally when a series is hidden; medians and quantiles must be recomputed. Each stat should therefore declare whether it is monoidal. Stats that produce proportions should state their normaliser: the probabilistic grammar of graphics shows that ggplot2 silently pieces together conditional densities "without normalizing by cyl group counts" ([Pu & Kay 2020](https://doi.org/10.31219/osf.io/dy8qv)). Kindlmann and Scheidegger's invariance principles give a test harness: changing the data representation must not change the picture, and changing the data must ([Kindlmann & Scheidegger 2014](https://vis.cs.ucdavis.edu/vis2014papers/TVCG/papers/2181_20tvcg12-kindlmann-2346325.pdf)). Julia's multiple dispatch is well suited to the newest domain extensions. ggtime adds temporal granularities and time zones ([Huang et al. 2025](https://arxiv.org/abs/2510.25656)), ggdibbler treats random-variable inputs ([Mason et al. 2026](https://arxiv.org/abs/2606.24217)), and ggdist needed custom scale sharing because "faceting doesn't cut it" ([Kay 2024](https://mucollective.northwestern.edu/files/2023-ggdist.pdf)). In Julia, the same behaviour can come from dispatch on column element types (`Date`, `ZonedDateTime`, `Distribution`) instead of new geoms, provided new aesthetic and scale types are first-class extension points.

The surface syntax should avoid ggplot2's specific traps. `+` dispatch problems were part of the reason for the S7 migration ([#3986](https://github.com/tidyverse/ggplot2/issues/3986)). Non-standard evaluation produces two top-voted questions: "no visible binding for global variable" and how to pass a column name in a variable ([SO 9439256](https://stackoverflow.com/questions/9439256)). Julia `Symbol` column references and composition on plain immutable values remove both problems; seaborn.objects' methods likewise "return cloned objects rather than modifying in place" ([seaborn.objects](https://seaborn.pydata.org/tutorial/objects_interface.html)). Kay observes that JavaScript cannot match ggplot2's succinctness without facilities for "capturing and re-writing abstract syntax trees" ([Kay 2024](https://mucollective.northwestern.edu/files/2023-ggdist.pdf)), and Julia has them in macros. Familiar ggplot2 vocabulary has real adoption value: lets-plot markets itself as "a faithful port of R's ggplot2" ([lets-plot](https://lets-plot.org/)), and TidierPlots exists because Julia users want that syntax. For "very little code", a call with no geom, such as `chart(df, :region, :sales)`, can pick a mark from the field types in the way Show Me does. The result must still be an ordinary, editable grammar object. A 2026 preprint goes further and argues that "a chart may be declarative; authoring it is not", modelling authoring as a chain of actions that LLMs interpret more reliably ([Jeon & Seo 2026](https://arxiv.org/abs/2609.14353)). That is unreviewed, but a serialisable edit history alongside the spec costs little.

Finally, the compiler should follow Vega-Lite's proven phases. It normalises composite marks and shortcuts into core constructs, builds a tree of view models, parses them into mergeable components (data, scales, guides, marks, selections), de-duplicates shared scales and data, and only then assembles the target ([vega-lite compile.ts](https://github.com/vega/vega-lite/blob/main/src/compile/compile.ts)). The output of the merge step, the "built plot", should be public, documented API, as ggplot2's build output became de facto.

## Professional defaults are a newsroom consensus that should be encoded as rules

The evidence supports "minimalism within reason", not Tufte's absolutism. Wilke calls the qualifier on maximising the data–ink ratio "critical and frequently forgotten" ([Wilke 2019](https://clauswilke.com/dataviz/balance-data-context.html)). Embellished charts were described no less accurately than plain ones and **recalled significantly better after two to three weeks** ([Bateman et al. 2010](https://dl.acm.org/doi/10.1145/1753326.1753716)). Readers did not penalise heavily annotated charts and preferred the most annotated ones ([Stokes et al. 2022](https://people.ischool.berkeley.edu/~hearst/papers/tvcg2022.pdf)). Titles determine the message readers retain ([Borkin et al. 2016](https://vcg.seas.harvard.edu/publications/20150101-beyond-memorability-visualization-recognition-and-recall/paper)). Several layout defaults have direct empirical support. A crowdsourced replication of Cleveland and McGill corroborated **gridline alpha of 0.2** as a safe default, found that gridlines should be at least 8 pixels apart, and found "little benefit for increasing chart height beyond 80 pixels" for value comparison ([Heer & Bostock 2010](https://idl.cs.washington.edu/files/2010-MTurk-CHI.pdf)). Gridlines also reduce the sine illusion in line charts ([Knittel et al. 2024](https://arxiv.org/html/2408.00854)). Truncating the y axis increases perceived effect size even when the truncation is visibly marked ([Correll et al. 2020](https://arxiv.org/abs/1907.02035)). Bars therefore need a hard zero baseline, while lines can use data-fitted limits with a lint that flags exaggerated changes.

Newsroom and government house styles agree strongly with each other. The BBC's `bbc_style()` drops axis titles, ticks, axis lines, minor and vertical gridlines. It keeps light horizontal gridlines (#cbcbcb), uses #222222 text and puts the legend at the top without a title ([bbplot source](https://raw.githubusercontent.com/bbc/bbplot/master/R/bbc_style.R)). The Urban Institute uses Lato, a top legend, sparse gridlines, zero-based bars, direct labels and WCAG AA contrast ([Urban style guide](https://urbaninstitute.github.io/graphics-styleguide/)). The UK Government Analysis Function asks for a headline title stating the main message, a statistical subtitle, horizontal text only, line-end labels instead of legends, and never a broken bar axis ([Analysis Function](https://analysisfunction.civilservice.gov.uk/policy-store/data-visualisation-charts/)). Datawrapper adds tabular lining figures, labels of at least 12 px and sentence case ([Datawrapper, fonts](https://www.datawrapper.de/blog/fonts-for-data-visualization)), with left-aligned text and direct labels ([Datawrapper, text](https://www.datawrapper.de/blog/text-in-data-visualizations)). The Economist sets type in points at fixed one- and two-column print widths ([Economist style guide 2017](https://sa.ipaa.org.au/wp-content/uploads/2026/02/Economist-CHARTstyleguide_20170505.pdf)), and *Nature* asks for 5–7 pt figure text at final size ([Nature artwork guide](https://www.nature.com/documents/NRJs-guide-to-preparing-final-artwork.pdf)). ggplot2's grey panel has a reasoned defence: it gives the plot "a similar typographic colour to the text" ([ggplot2 book, Themes](https://ggplot2-book.org/themes.html)). It is nonetheless the most-undone default, and newer libraries default to white, minimal themes. lets-plot uses `theme_minimal2` and G2 ships a separate `academy` theme for papers ([lets-plot source](https://github.com/JetBrains/lets-plot/blob/master/python-package/lets_plot/plot/theme_set.py); [G2 themes](https://g2.antv.antgroup.com/en/manual/core/theme/overview)). One caution applies: cowplot replaced ggplot2's theme on load and reversed this in 1.0.0, a sign that opinionated defaults must be explicit ([cowplot NEWS](https://wilkelab.org/cowplot/news/index.html)).

Highcharts' polish can be traced in its source to tuned interaction-state defaults. Series animate in over **1,000 ms**. Hovering a series fades the others to **opacity 0.2** over 150 ms, and hovered points get a 0.25-opacity halo ([Highcharts SeriesDefaults.ts](https://github.com/highcharts/highcharts/blob/master/ts/Core/Series/SeriesDefaults.ts)). The neutral ramp keeps grid lines at #e6e6e6 while labels stay at #333333, and a system font stack scales from one root size ([highcharts.css](https://github.com/highcharts/highcharts/blob/master/css/highcharts.css)). These are design tokens, and they can be copied whatever the backend.

Colour defaults have strong evidence. Rainbow and jet maps create false boundaries and "perform the worst overall" ([Crameri et al. 2020](https://www.nature.com/articles/s41467-020-19160-7); [Liu & Heer 2018](https://idl.cs.washington.edu/files/2018-QuantitativeColor-CHI.pdf)). Viridis-type maps built in CAM02-UCS perform well, and cividis gives "nearly-identical visual-data interpretation" for readers with and without red–green colour-vision deficiency, which affects about 8% of men and 0.5% of women ([Nuñez et al. 2018](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0199239)). For categorical data, Petroff's sequences come from a preference model trained on crowdsourced data, under perceptual-distance, CVD and greyscale constraints. matplotlib 3.10 now ships them ([Petroff 2024](https://arxiv.org/abs/2107.02270); [matplotlib petroff10](https://matplotlib.org/stable/gallery/style_sheets/petroff10.html)). Szafir shows that colour differences needed for discrimination grow as marks shrink, so thin lines need larger hue gaps than bars ([Szafir 2018](http://danielleszafir.com/colordiff_vis2017.pdf)). The library should therefore interpolate in OKLab ([Ottosson 2020](https://bottosson.github.io/posts/oklab/)) and lint palette distances against mark size. It should also ship generators, not just lists: Colorgorical-style scoring lets a brand theme derive an accessible palette from one or two brand hues ([Gramazio et al. 2017](http://vrl.cs.brown.edu/color/pdf/colorgorical.pdf)). Four layout algorithms complete the "looks right by default" layer. The first is Talbot's tick labeller, which weights simplicity, coverage, density and legibility at 0.2, 0.25, 0.5 and 0.05 and treats the label format as part of the search ([Talbot et al. 2010](http://vis.stanford.edu/files/2010-TickLabels-InfoVis.pdf)). The second is d3's calendar interval ladder with a concise multi-level date formatter ([d3-scale time](https://d3js.org/d3-scale/time)). The third is line-end label dodging plus seeded repulsion for scatter labels ([ggrepel](https://ggrepel.slowkow.com/articles/examples.html)), and the fourth is number formatting derived from the tick step ([d3-format](https://d3js.org/d3-format)). Rotated tick labels, the subject of the top-voted ggplot2 question, should be treated as a failure of tick and format choice, not a theme setting.

The theme system should be a typed, three-tier token tree. Primitives (palettes, font files, base size) feed semantic tokens (`ink`, `paper`, `accent`, `muted`, `grid`). Element styles inherit from those tokens through documented selectors. ggplot2 4.0 shows the payoff: `ink`, `paper` and `accent` arguments restyle a whole theme, layer defaults come from `element_geom()`, and palettes live in the theme ([ggplot2 styling post](https://tidyverse.org/blog/2025/10/ggplot2-styling/)). Vega-Lite shows precedence done explicitly: "type-based options take precedence over orientation-based options, which in turn take precedence over general options" ([Vega-Lite config](https://vega.github.io/vega-lite/docs/config.html)). Highcharts shows the customisation ceiling worth matching. Options cascade from global through series-wide and type-specific defaults down to individual series and points ([Highcharts options](https://www.highcharts.com/docs/getting-started/how-to-set-options)), and responsive rules stack overrides that revert when a width condition stops applying ([Highcharts responsive](https://www.highcharts.com/docs/chart-concepts/responsive)). Themes should be serialisable to the W3C Design Tokens format, whose first stable version appeared in October 2025 ([W3C DTCG](https://www.w3.org/community/design-tokens/2025/10/)). They should map to CSS custom properties on the web, as Highcharts' styled mode does ([Highcharts CSS styling](https://www.highcharts.com/docs/chart-design-and-style/style-by-css)) and as ECharts 6 now does with design tokens and automatic dark mode ([ECharts 6](https://echarts.apache.org/handbook/en/basics/release-note/v6-feature/)). Then one theme drives print, HTML and dark mode identically.

Defaults should be rules held as data, not constants in code. Mackinlay's expressiveness criterion (encode all the facts and only the facts) gives hard constraints. His effectiveness ranking, by his own account, "has not been empirically verified" beyond the quantitative case ([Mackinlay 1986](https://dl.acm.org/doi/10.1145/22949.22950)). Later work shows rankings shift with task and cardinality ([Kim & Heer 2018](https://idl.cs.washington.edu/files/2018-TaskDataEffectiveness-EuroVis.pdf)) and with the individual ([Davis et al.](https://arxiv.org/abs/2212.10533)). Precision is also not the only goal ([Bertini et al. 2020](https://arxiv.org/abs/2008.11310)), and pie charts now look like area rather than angle encodings ([Zeng & Battle 2023](https://arxiv.org/abs/2109.01271)). Draco's model of hard constraints plus weighted soft constraints that "can easily be augmented" fits this situation ([Moritz et al. 2019](https://idl.cs.washington.edu/files/2019-Draco-InfoVis.pdf)). A Julia version can be a dispatch-driven cost model that fills unspecified properties, lints specified ones and explains which rule fired. LLMs should not set these weights: GPT-4-Turbo's derived design preferences "correlate weakly" with empirically learned costs ([DracoGPT](https://arxiv.org/abs/2408.06845)).

## Annotations need data targets, not hand-typed coordinates

Text is the strongest non-data element in a chart, and the evidence argues for making it a first-class part of the grammar. Readers' recall of a chart's message "more frequently aligned with the titles than the visualization" ([Kong et al. 2019](https://dl.acm.org/doi/10.1145/3290605.3300576)). Readers "first focus on the title", and statistical text produces statistical takeaways ([Stokes et al. 2022](https://people.ischool.berkeley.edu/~hearst/papers/tvcg2022.pdf)). Wickham's 2010 grammar nevertheless dropped annotation guides as constructible "with creative use of geoms" ([Wickham 2010](https://vita.had.co.nz/papers/layered-grammar.pdf)). Practice shows the cost. Only "a handful" of the 57 JSON visualization DSLs surveyed have top-level annotation support, Highcharts among them ([McNutt 2022](https://arxiv.org/abs/2207.07998)). AnnoGram compared eight tools and found that ggplot2's `annotate` and Highcharts' annotations reduce initial effort, but "weak semantic coupling still requires manual adjustments during updates" ([Rahman et al. 2025](https://arxiv.org/abs/2507.04236)). Its remedy is a top-level annotation primitive alongside scales and geometries, specifying a target, an effect and a placement strategy. Studies of news graphics supply the vocabulary. ChartAccent's design space comes from 106 annotated charts by six graphics desks and supports data-driven targets such as min, max, mean and median ([ChartAccent](https://chartaccent.github.io/)). A later qualitative analysis covers more than 1,800 annotated charts ([Rahman et al. 2025](https://arxiv.org/abs/2306.06043)).

The design that follows has three parts. Targets are data queries (the last point of a series, the argmax, a date range, a mean line), not coordinates typed by hand. Positions combine data, panel-relative and absolute units (`x = data(1950) + pt(4)`). That closes the gap behind ggplot2's open unit issue ([#5609](https://github.com/tidyverse/ggplot2/issues/5609)) and the partial `I()` fix of 3.5.0. Annotations escape the panel's clip region on request, which ggplot2 still cannot do per layer ([#6773](https://github.com/tidyverse/ggplot2/issues/6773)). Because annotations are layers bound to data, they survive filtering, faceting, legend toggling and drilldown, and they can be exported as alt-text fragments. "Highlight one series and mute the rest" should be a single operation, because it is the most common newsroom pattern and the same visual state as hover dimming. Tooltips are then transient annotations attached to a hovered target. Titles and subtitles can be templated from data, with a lint that warns when a title's claimed direction contradicts the data, because slanted titles shape recall even when readers believe the chart is impartial ([Kong et al. 2019](https://dl.acm.org/doi/10.1145/3290605.3300576)).

This also sets a rule for interactivity. The New York Times' deputy graphics director told practitioners in 2016: "If you make a tooltip or rollover, assume no one will ever see it. If content is important for readers to see, don't hide it" ([Tse 2016](https://github.com/archietse/malofiej-2016/blob/master/tse-malofiej-2016-slides.pdf)). The counter-evidence is that readers do use interactivity "when it is a core part of the article's message" ([Hohman et al. 2020](https://distill.pub/2020/communicating-with-interactive-articles/)). Either way, the static reading must be complete, and interaction should only add detail. The widely repeated claim that only 10–15% of NYT readers interact could not be traced to a primary source.

## Highcharts behaviours should compile to a data-space selection algebra

The interaction taxonomies converge on a short list of user intents: select, explore, reconfigure, encode, abstract or elaborate, filter and connect ([Yi et al. 2007](https://faculty.cc.gatech.edu/~stasko/papers/infovis07-interaction.pdf)). Shneiderman's "overview first, zoom and filter, then details on demand" ([Shneiderman 1996](https://www.cs.umd.edu/~ben/papers/Shneiderman1996eyes.pdf)) and Heer and Shneiderman's twelve tasks ([Heer & Shneiderman 2012](https://idl.cs.washington.edu/files/2012-InteractiveDynamics-CACM.pdf)) describe the same space. Highcharts-style presentation charts use a small, predictable subset: shared or split tooltips, an inactive state that dims other series, legend click-to-toggle, drag-zoom with a range navigator, and drilldown. In Highcharts drilldown, a clicked point loads a child series, with breadcrumbs, a drill-up button and asynchronous loading through an event ([Highcharts drilldown](https://www.highcharts.com/docs/chart-concepts/drilldown)). Exploratory analysis adds brushing and linking, crossfiltering and dynamic queries. A language that serves both audiences needs both levels of abstraction, and the evidence favours building the first on the second.

The research identifies three families of interaction design. In the first, interaction is integrated into the grammar as data-space selections. Vega-Lite's point and interval selections drive conditional encodings, filters and scale domains. They bind to legends and to scales (pan and zoom), and the paper reports typical interactions in "1-2 lines" against "tens of lines" in Reactive Vega ([Satyanarayan et al. 2017](https://idl.cs.washington.edu/files/2017-VegaLite-InfoVis.pdf)). Mosaic generalised this by decoupling selections from input events and adding crossfilter resolution. It sustains interaction over the **1.8 billion stars of the Gaia catalogue** by pushing queries to DuckDB ([Heer & Moritz 2024](https://idl.cs.washington.edu/files/2024-Mosaic-TVCG.pdf)). In the second, interaction is a set of named behaviours with styled states. G2 declares `interaction: { tooltip: {}, brushHighlight: {} }` per view or mark, styles marks through `active`, `inactive`, `selected` and `unselected` states, and exposes an event bus ([G2 interaction docs](https://g2.antv.antgroup.com/en/manual/core/interaction/overview)). ggiraph adds `tooltip`, `data_id` and `onclick` aesthetics, and the same plot object prints statically or renders as interactive SVG ([ggiraph](https://davidgohel.github.io/ggiraph/)). animint's `clickSelects` and `showSelected` aesthetics put linked selection into ggplot2 syntax with a compiler/renderer split ([Sievert et al. 2019](https://doi.org/10.1080/10618600.2018.1513367)). In the third, interaction is a separate layer: Libra's instruments and services ([Zhao et al. 2025](http://www.yunhaiwang.net/CHI2025/Libra/files/paper.pdf)), and DIVI, which infers interactions from rendered SVG ([Snyder & Heer 2024](https://idl.cs.washington.edu/files/2024-DIVI-TVCG.pdf)). One cautionary precedent: ggvis's authors still "believe… reactive programming is the right foundation for interactive visualisation", but the package is dormant because interactivity was not the R community's most pressing need ([ggvis README](https://github.com/rstudio/ggvis)).

The strongest design uses selections as the semantic core, named behaviours as the default user surface, and a separable interaction subtree that static and accessible backends can drop or translate.

| Tier | User-facing form | Internal meaning | Precedent |
|---|---|---|---|
| 0: default behaviours | On unless switched off: tooltip, hover highlight with dimming, legend toggle, keyboard navigation; one keyword for `zoom = :x`, crosshair, range navigator | Compiled to Tier-2 selections and theme state styles | Highcharts, [G2](https://g2.antv.antgroup.com/en/manual/core/interaction/overview) |
| 1: interaction aesthetics | `tooltip =`, `id =`, `href =`, `drill =` mapped like any aesthetic | Keys for object constancy, linking and parent→child drilldown | [ggiraph](https://davidgohel.github.io/ggiraph/), [animint](https://doi.org/10.1080/10618600.2018.1513367) |
| 2: selection algebra | Point and interval selections; resolve by union, intersect or crossfilter; bind to legends, scales and widgets | Predicates over data fields, obtained by scale inversion | [Vega-Lite](https://vega.github.io/vega-lite/docs/selection.html), [Mosaic](https://idl.cs.washington.edu/files/2024-Mosaic-TVCG.pdf) |
| 3: escape hatch | Custom event streams or instruments | Runtime hooks | [Reactive Vega](https://idl.cs.washington.edu/files/2015-ReactiveVega-InfoVis.pdf), [Libra](http://www.yunhaiwang.net/CHI2025/Libra/files/paper.pdf) |

Keeping all interaction state in the data domain is the decision that makes everything else work. A selection defined as a predicate over fields can be frozen for static export, read aloud by a screen reader, pushed to a database, driven by a timer for animation, or set from the keyboard. A selection defined in pixels can do none of these. Hit-testing belongs in the grammar too. Observable Plot's pointer transform renders only the nearest point within 40 px, and its one-dimensional mode for charts with a dominant axis divides the other distance by 100 ([Plot pointer](https://observablehq.com/plot/interactions/pointer)). Vega-Lite's `nearest` uses a Voronoi diagram, and Highcharts uses a k-d tree ([Highcharts boost](https://www.highcharts.com/docs/advanced-chart-features/boost-module)). These make tooltips easy to trigger without depending on the DOM. The default tooltip should list mapped channels formatted by their scales, as Plot's `tip` mark does, so it needs no code. Zoom is an interval selection bound to scale domains, and it should re-run view-dependent statistics such as M4 downsampling for the new range. Drilldown is a Tier-1 key into a nested dataset or spec, with breadcrumbs, a static fallback (the current level, or small multiples of the children) and optional asynchronous loading from a live Julia session. Legend toggling re-stacks only through stats that declared themselves monoidal.

Animation needs two constructs and conservative defaults. Animated transitions between related views help viewers track change, and simple staging helps, though "the advantages are not overwhelming". Transitions should be "as long as needed, but no longer", around one second ([Heer & Robertson 2007](https://idl.cs.washington.edu/files/2007-AnimatedTransitions-InfoVis.pdf)). Gapminder-style animation as the medium of analysis is fast and enjoyable but error-prone; small multiples were more accurate ([Robertson et al. 2008](https://faculty.cc.gatech.edu/~stasko/papers/infovis08-anim.pdf)). The grammar therefore needs, first, a `transition` between spec states keyed by `id` for object constancy, staged internally the way Gemini stages steps (axes first, then marks, then enter/exit) ([Kim & Heer 2021](https://arxiv.org/abs/2009.01429)). Second, it needs `time` as an aesthetic, compiled to a play/pause/scrub control that is internally a timer-driven selection, following Animated Vega-Lite's observation that "interaction and animation are parallel concepts" ([Zong et al. 2022](https://arxiv.org/abs/2208.03869)). ECharts' defaults, **500 ms updates** and animation disabled above **2,000 elements** ([ECharts globalDefault.ts](https://github.com/apache/echarts/blob/master/src/model/globalDefault.ts)), are sensible starting points. Publication output should have no decorative entrance animation. Motion should respect `prefers-reduced-motion` and WCAG's pause/stop/hide requirement ([WCAG 2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)). Static export of a time-animated chart should default to small multiples or trails, not the last frame.

## Own the scene and the text metrics; use JavaScript libraries only as runtimes

Dual output fails in four predictable ways. Fonts drift: ggiraph warns that a font missing on the reader's machine leaves text "badly positioned", so it bundles Liberation fonts ([ggiraph fonts](https://www.ardata.fr/ggiraph-book/fonts.html)). Raster islands appear: Plotly's WebGL traces become "encapsulated rasters" in vector exports ([Plotly static export](https://plotly.com/python/static-image-export/)), and Plotly Express switches to WebGL above 1,000 rows ([Plotly performance](https://plotly.com/python/performance/)). Runtime dependencies creep in: Kaleido 1.0 requires an installed Chrome ([Kaleido README](https://github.com/plotly/Kaleido/blob/master/src/py/README.md)). And interaction is lost on export: WGLMakie's standalone 2-D export is "completely static" because zoom and inspection run in Julia ([WGLMakie docs](https://docs.makie.org/stable/explanations/backends/wglmakie)).

The systems that avoid these failures share one architecture: a renderer-neutral scene compiled once and consumed by several renderers. Examples are TanStack Charts' "renderer-neutral scene" ([TanStack Charts](https://tanstack.com/charts/latest/docs/concepts/grammar-of-graphics)), Kandy's Plot Intermediate Representation with lets-plot and ECharts backends ([JetBrains](https://blog.jetbrains.com/kotlin/2023/12/kandy-the-new-kotlin-plotting-library-by-jetbrains/)), and animint's compiler/renderer split. For a Julia grammar the scene should be fully resolved in Julia. Fonts come from actual files and are measured once. Tick collisions, legend wrapping and margins are decided once. Fonts are embedded and subset into both PDF and HTML, and the web runtime receives pre-measured positions to place, not text to re-flow. Physical units with a declared pixel mapping serve print. Responsive web resizing re-runs the same layout algorithm at the new width instead of scaling it with CSS. Every Tier-0 behaviour declares its static fallback. Legend state and zoom domain export as they stand, tooltips can become direct labels for flagged points, and drilldown exports the current level or a facet of its children.

The web target is constrained by licences and spec churn as much as by features, as of October 2026:

| Target | Version | Licence | JS for a basic interactive chart (gzip) | Static export without a browser | Fit to the brief |
|---|---|---|---|---|---|
| Vega-Lite + Vega | 6.5.0 (8 Oct 2026) | BSD-3 | ≈274 KB | Yes: vl-convert embeds V8 | Grammar with selections; no drilldown or built-in animation |
| Apache ECharts | 6.1.0 (May 2026) | Apache-2.0 | 359 KB full, 165 KB simple | Yes: zero-dependency SSR to SVG strings | Chart-type model; dataZoom, brush, legend toggle, drill-down transitions, v6 tokens and dark mode |
| Plotly.js | 4.1.2 (5 Oct 2026) | MIT | 1,441 KB full, 388 KB basic | No: Kaleido 1.x needs Chrome | Trace model; rich hover and zoom; breaking majors in Jan 2025 and Aug 2026 |

| Observable Plot | 0.6.17 (Feb 2025) | ISC | ≈157 KB with D3 | "Only practical for simple plots of small data" | Concise grammar; tips and crosshair only |

Sources: [npm registry](https://www.npmjs.com/package/vega-lite) versions and licences; [vl-convert](https://github.com/vega/vl-convert); [ECharts SSR](https://apache.github.io/echarts-handbook/en/how-to/cross-platform/server/); [plotly.js dist](https://github.com/plotly/plotly.js/blob/master/dist/README.md); [Highcharts changelog](https://changelog.highcharts.com/); [Observable Plot](https://www.npmjs.com/package/@observablehq/plot). Gzip sizes were measured by the researchers from jsDelivr builds.

The Highcharts EULA of 20 January 2026 settles one question. Free use covers personal use and accredited-education use only. "Commercial Use" explicitly includes "any use within a for-profit company, non-profit organization, or government entity", including prototyping and internal presentations. Licensees may not make the compiled software available to any third party, and commercial use of the Highcharts CDN is prohibited ([Highcharts EULA 1.0](https://shop.highcharts.com/license-eula-1.0.pdf)). The core costs **$366 per developer seat per year** ([Highcharts shop](https://shop.highcharts.com/)). The R wrapper highcharter still bundles Highcharts 12.6.0 ([highcharter](https://github.com/jbkunst/highcharter/blob/main/inst/htmlwidgets/highchart.yaml)), which sits uneasily with that clause. A Julia library aimed at researchers, companies and governments can therefore offer Highcharts only as an opt-in emitter that loads JavaScript the user licenses. Highcharts remains the behavioural specification to imitate.

The evidence points to a primary path plus secondary emitters. The steelman for emitting ECharts options alone is strong. It is Apache-2.0. It already has legend, tooltip, dataZoom, brush and visualMap components, automatic ARIA descriptions and "millions of data points" through incremental rendering ([ECharts features](https://echarts.apache.org/en/feature.html)), plus drill-down transitions since 5.5 ([ECharts changelog](https://echarts.apache.org/en/changelog.html)). It would cost a fraction of the work. Its costs are structural. ECharts measures and lays out text itself, so print output from Julia and interactive output from ECharts would come from two layout engines and could not be guaranteed to match. Its "colloquial" chart-type model has no composition algebra and "relies on the browser for spatial arrangement" ([McNutt 2022](https://arxiv.org/abs/2207.07998)). Styling is bounded by its option tree. The primary path should therefore be the Julia-resolved scene. A small owned runtime would draw it as SVG, switching to Canvas for dense layers, and implement Tier 0, Tier 1 and the common Tier-2 selections. Gadfly once shipped exactly this kind of self-contained SVG interactivity with Snap.svg ([Gadfly docs](http://gadflyjl.org/stable/)). Emitters to Vega-Lite (for interoperability and schema-checked JSON) and ECharts (for breadth) can follow as extensions. Every web target ships a breaking major every 1.5 to 4 years, so each emitter must pin target versions and test generated specs against the target's schema. For notebooks, self-contained `text/html` is safer than versioned MIME renderers. Altair 6 now defaults to an HTML renderer ([Altair display.py](https://github.com/vega/altair/blob/main/altair/vegalite/v6/display.py)), and JupyterLab's own docs still list only Vega 5 and Vega-Lite 3 ([JupyterLab issue](https://github.com/jupyterlab/jupyterlab/issues/8026)).

Scale needs a hybrid renderer and data reduction treated as statistics. Industry thresholds are consistent but come from vendors, not peer review. ECharts recommends Canvas above about 1,000 elements ([ECharts Canvas vs SVG](https://echarts.apache.org/handbook/en/best-practices/canvas-vs-svg/)), and uPlot draws **166,650 points in 25 ms** on Canvas 2D ([uPlot](https://github.com/leeoniya/uPlot)). Highcharts switches to WebGL at 5,000 points per series and reaches 1 million scatter points, but in exchange it loses dashes, most marker shapes, animation and stacking ([Highcharts boost](https://www.highcharts.com/docs/advanced-chart-features/boost-module)). Plotly warns that more than 8 WebGL figures on one page can fail because of browser context limits ([Plotly performance](https://plotly.com/python/performance/)). Guides, text and annotations should therefore always be SVG or HTML, and data layers should be promoted per layer, with a warning when promotion drops features. Downsampling belongs in the grammar as view-dependent statistics. M4 (min, max, first and last per pixel column) is provably error-free for line charts and cuts data by up to two orders of magnitude ([Jugel et al. 2014](https://www.vldb.org/pvldb/vol7/p797-jugel.pdf)). MinMaxLTTB is more than ten times faster than LTTB ([Van Der Donckt et al. 2023](https://arxiv.org/abs/2305.00332)). Plotly-Resampler re-aggregates on zoom and marks aggregated series with an "[R]" prefix ([Van Der Donckt et al. 2022](https://arxiv.org/abs/2206.08703)). In a live Julia session a Mosaic-style coordinator can push filters to DuckDB.jl. Falcon shows **50 fps** brushing and linking with constant performance whatever the data size ([Moritz et al. 2019](https://idl.cs.washington.edu/files/2019-Falcon-CHI.pdf)). Wickham's bin-summarise-smooth argument still frames the goal: there is no point drawing more marks than the roughly three million pixels available ([Wickham 2013](http://vita.had.co.nz/papers/bigvis.pdf)).

## Accessibility can be generated from the spec instead of bolted on

Industry practice treats accessibility as an add-on. Highcharts' accessibility module is "not loaded by default", although Highsoft recommends always including it. It provides keyboard navigation, screen-reader regions, point descriptions, data tables, live announcements and sonification ([Highcharts accessibility](https://www.highcharts.com/docs/accessibility/accessibility-module)). Among 57 JSON visualization DSLs, only Highcharts, Vega-Lite, ECharts and FusionCharts provide their own accessibility features ([McNutt 2022](https://arxiv.org/abs/2207.07998)). Datawrapper sets the out-of-the-box bar. It keeps text readable on any background automatically, checks colour-blindness, generates screen-reader descriptions such as "Line chart with 7 lines" and supports arrow-key navigation ([Datawrapper accessibility](https://www.datawrapper.de/academy/how-we-make-sure-our-charts-maps-and-tables-are-accessible)).

Research shows that a grammar already holds everything needed to generate accessible structure. Zong and colleagues define three dimensions: structure (how chart entities are organised for traversal), navigation (local, lateral across facets, spatial and targeted) and description. They tested this with 13 blind and visually impaired readers ([Zong et al. 2022](https://vis.csail.mit.edu/pubs/rich-screen-reader-vis-experiences.pdf)). Lundgard and Satyanarayan's four levels of description show that blind readers find statistical (L2) and perceptual-trend (L3) content most useful. **63%** of blind participants objected to authors' subjective interpretation (L4) ([Lundgard & Satyanarayan 2022](https://vis.csail.mit.edu/pubs/vis-text-model.pdf)). Olli converts Vega, Vega-Lite and Observable Plot specs into an ARIA tree through adapters ([Blanco et al. 2022](https://vis.csail.mit.edu/pubs/olli.pdf)). Umwelt derives visual, textual and sonified views from one data model and keeps "a shared query predicate that is reified across all modalities" ([Zong et al. 2024](https://arxiv.org/abs/2403.00106)). Data Navigator's navigation graph works over raster and WebGL renderers ([Elavsky et al. 2024](https://arxiv.org/abs/2308.08475)). Erie treats sonification as a grammar in which a tone is "roughly analogous to a mark" ([Kim et al. 2024](https://arxiv.org/abs/2402.00156)). Chartability provides ten critical heuristics, among them low contrast, small text, interaction with only one input, and no title, summary, caption or table ([Elavsky et al. 2022](https://www.domoritz.de/papers/2022-Chartability.pdf)).

The implication is a compile-time pipeline that is on by default, not an optional module. The compiler should emit an ARIA tree from the spec (chart, facets, axes and legends, intervals, points), with lateral edges between facets. It should generate L1 descriptions from the spec and compute L2 statistics in Julia, label any L3 trend summaries as heuristic, and leave L4 to the author. Every Tier-0 behaviour needs a keyboard binding, which is straightforward because selections are decoupled from input events. Legend, filter and drilldown changes should be announced through `aria-live`, a data table should always be available, and sonification can be one more renderer of the same scene. The same rules engine that sets visual defaults can lint WCAG requirements. These include 3:1 contrast for graphical objects needed for understanding, so adjacent pie slices need separators unless labels and values are shown ([WCAG 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)). They also include 4.5:1 text contrast, colour-only encodings, text below about 12 px or 6 pt, and palette pairs that collapse under Machado's colour-vision-deficiency simulation ([Machado et al. 2009](https://www.inf.ufrgs.br/~oliveira/pubs_files/CVD_Simulation/Machado_Oliveira_Fernandes_CVD_Vis2009_final.pdf)). Three gaps remain open. Accessible zoom and brushing for screen-reader users is largely unresearched. Auto-generated L2 descriptions from a grammar compiler have not been evaluated. Tagged-PDF output was not researched.

## Julia's missing piece is a grammar that exports live HTML, not another static layer

Makie is the most complete native system. Version 0.24.15 (September 2026) replaced Observables with a ComputeGraph and has a declarative SpecApi. CairoMakie's PDF and SVG output now keeps each text string as one editable object ([Makie CHANGELOG](https://github.com/MakieOrg/Makie.jl/blob/master/CHANGELOG.md)). Its web story is the weak point. WGLMakie's 2-D HTML export is static; zoom logic is "all implemented in Julia, so not available in a pure javascript export" ([Julia Discourse 2025](https://discourse.julialang.org/t/wglmakie-zoom-with-export-static/126585)). Hover tooltips for offline export are an open pull request as of October 2026 ([Makie PR #5715](https://github.com/MakieOrg/Makie.jl/pull/5715)). Every minor release from 0.20 to 0.24 was breaking, and SpecApi is still marked as liable to "introduce breaking changes" ([Makie SpecApi](https://docs.makie.org/stable/explanations/specapi)). That is a real dependency risk for anything built on top of Makie.

The grammar layers on Makie confirm where the gap is. AlgebraOfGraphics 0.13 (June 2026) finished a scales rewrite that made statistics fit in transformed space ([AoG CHANGELOG](https://github.com/MakieOrg/AlgebraOfGraphics.jl/blob/master/CHANGELOG.md)). Its most-upvoted open issues are about theming documentation (open since 2021), error bars, animations and legend interactivity ([AoG issues](https://github.com/MakieOrg/AlgebraOfGraphics.jl/issues?q=is%3Aopen+sort%3Areactions-%2B1-desc)). One experienced user said that outside "the 'happy path'… I fight the 'grammar' more than it helps me" ([Julia Discourse](https://discourse.julialang.org/t/algebraofgraphics-documentation-frustrations/133903)). TidierPlots reached 1.0 in January 2026 as a ggplot2 clone on Makie's SpecApi, having dropped AoG in 2024. Its README still answers the question of why anyone would use it with "**Right now, you probably wouldn't**" ([TidierPlots](https://github.com/TidierOrg/TidierPlots.jl)). Gadfly, the original ggplot-like library, had Snap.svg interactivity and is still praised, but its first plots took "tens of seconds" and it has had no feature release since 2021 ([Gadfly](http://gadflyjl.org/stable/)). Plots.jl's recipe system shows the extension pattern to copy: more than 300 packages define recipes through a lightweight dependency ([Christ et al. 2023](https://doi.org/10.5334/jors.431)). Its meta-backend design shows the pattern to avoid. Makie's authors note that it exposes "only a limited subset of each backend's functionality" ([Danisch & Krumbiegel 2021](https://doi.org/10.21105/joss.03349)), and the Plots 2.0 pull request has been open since March 2024 ([Plots PR #4904](https://github.com/JuliaPlots/Plots.jl/pull/4904)).

Demand for the missing piece is visible. Users ask repeatedly how to keep pan and zoom in saved HTML, and the usual answer points them out of the grammar world to PlotlyJS ([Julia Discourse 2026](https://discourse.julialang.org/t/interactive-line-plots-in-documentation/135537)). ECharts.jl was revived in 2026 on the pitch that "most Julia plotting libraries either produce static images or require verbose configuration to get basic interactivity". It turns tooltips on automatically and shows a legend only with two or more series ([ECharts.jl](https://github.com/randyzwitch/ECharts.jl)). No Julia Highcharts wrapper exists ([GitHub search](https://github.com/search?q=highcharts+language%3Ajulia&type=repositories)). An astrophysicist preparing journal figures in February 2026 wrote that "my plots look vaguely amateurish so far" ([Julia Discourse](https://discourse.julialang.org/t/any-package-for-plots-in-style-of-scientific-journals/135378)). Time-to-first-plot was the top complaint in the 2020 Julia survey ([Christ et al. 2023](https://doi.org/10.5334/jors.431)), and in December 2023 CairoMakie carried 241 dependencies and a 3.58-second load against Plots' 62 and 1.30 seconds ([Kamiński 2023](https://bkamins.github.io/julialang/2023/12/01/plot.html)). An HTML path that renders in the browser can be light: PlotlyLight advertises the fastest time-to-first-plot in Julia, and an Observable Plot wrapper precompiles in under five seconds ([PlotlyLight](https://github.com/JuliaPlots/PlotlyLight.jl); [ObservablePlotExperiment](https://github.com/fonsp/ObservablePlotExperiment.jl)).

The new package should reuse Julia's infrastructure aggressively and build only three things. Tables.jl should be the data contract. Colors and ColorTypes, which now include OKLab and OKLCh ([ColorTypes](https://github.com/JuliaGraphics/ColorTypes.jl)), and ColorSchemes cover colour science. GridLayoutBase can serve as the layout solver, JSON.jl v1 should be used rather than JSON3, which its own README marks deprecated ([JSON3](https://github.com/quinnj/JSON3.jl)), and HypertextLiteral can generate HTML. PrecompileTools and package extensions keep the core light. Bonito is the natural transport only if live, server-backed interaction is wanted, and its 5.0 release in June 2026 was breaking and requires Julia 1.11 ([Bonito releases](https://github.com/SimonDanisch/Bonito.jl/releases)). The three things to build are a Talbot-complete tick labeller, text measurement and shaping, and the JavaScript runtime. PlotUtils' `optimize_ticks` is "basically Wilkinson's ad-hoc scoring method" without Talbot's legibility search ([PlotUtils ticks.jl](https://github.com/JuliaPlots/PlotUtils.jl/blob/master/src/ticks.jl)). Text measurement for non-Makie output rests on low-activity FreeType wrappers, and a 2026 TextMeasure.jl announcement shows the need is recognised ([Julia Discourse](https://discourse.julialang.org/t/ann-maketextrepel-jl-and-textmeasure-jl/137810)). No maintained Julia-side interaction runtime exists for 2-D charts.

The package should not compete with AlgebraOfGraphics on "grammar on Makie for static figures". It should interoperate instead: a Makie extension can lower the resolved scene to SpecApi for 3-D, GPU and existing Makie workflows, and recipe-style hooks through package extensions let domain packages target it cheaply. Vizagrams.jl, which combines a diagram algebra with a Vega-Lite-like spec on its own renderer ([Barreira et al. 2025](https://doi.org/10.21105/joss.09037)), is the closest Julia prior art for that "own scene" route.

## Conclusion

The research shifts the design problem away from where it is usually framed. The grammar itself is close to settled: Wickham's layers, an AoG-style spec algebra, a Polaris-style facet algebra and GoFish-style layout operators are compatible and well documented. The hard, irreversible decisions sit at the seams: where text is measured, which unit every position is in, whether interaction state is a data predicate or a pixel event, whether stats declare the laws that legend toggling and brushing rely on, and whether the compiled scene is public. ggplot2 spent 2016 to 2025 retrofitting exactly these seams. A Julia library that gets them right first can deliver "more customizable" as the absence of cliffs, "publication quality with little code" as rules-driven defaults that can be explained, and "Highcharts-style interaction" as a set of named behaviours compiled to selections, all from one spec. The Highcharts licence change of 2026 makes the strategic point concrete: polish is a set of tuned behaviours and tokens that can be specified and reimplemented, not a library to wrap.

The open risks are empirical and organisational. No study compares integrated and separated interaction authoring. No peer-reviewed benchmark fixes the SVG/Canvas/WebGL crossover. Generated accessibility descriptions have not been evaluated. Gadfly stalled after 2021 even though users still praise its API, a reminder that maintainer bandwidth decides whether a Julia plotting package survives. A JavaScript runtime adds a second codebase in a second language to that burden. The project should therefore validate as it builds. Kruchten-style notation metrics over a shared gallery give an objective measure of conciseness. Kindlmann-style invariance properties give a test suite for the grammar. Chartability's critical heuristics give an accessibility gate. And static and HTML renders of the same scene should be compared directly to keep drift between the two outputs at zero.
